4 SLIDE 3: What Is Pseudocode?

[0:06–0:10] — Definition

Pseudocode is a step-by-step description of what you want your code to do, written in plain language.

It’s not code. It’s not prose. It’s something in between.

Think of it as a recipe for analysis:

  • Clear enough that someone could follow it
  • Specific enough that there’s no ambiguity
  • General enough that you’re not writing actual code yet

Here are examples from both fields:

Biology - Bad (too vague): - “Clean the species data”

Biology - Better (pseudocode): - “Remove rows where species name is missing” - “Remove rows where species name contains obvious typos (checked against species list)” - “Standardize species names to match taxonomy database” - “Save cleaned data to data/processed/species_clean.csv”

Chemistry - Bad (too vague): - “Process the spectroscopy data”

Chemistry - Better (pseudocode): - “Load absorbance data from CSV file” - “Subtract baseline absorbance (measured at 800 nm)” - “Apply Beer-Lambert law to calculate concentrations” - “Remove concentrations outside calibration range (0-10 μM)” - “Save processed data to data/processed/concentrations.csv”

See the difference?

5 SLIDE 4: Why Pseudocode Matters

[0:10–0:14] — The Case for Planning

Why do we need pseudocode? Three reasons:

1. It forces you to think before you code

Most coding mistakes happen because people start typing before they know what they’re trying to do. Pseudocode makes you slow down and plan.

2. It reveals ambiguity

When you write “clean the data,” you think you know what you mean. But when you try to write pseudocode, you realize: What does “clean” mean? What counts as invalid? What do I do with missing values?

Biology example: “Remove outliers” — which outliers? Based on what criteria? Standard deviations? IQR? Domain knowledge?

Chemistry example: “Correct for drift” — linear drift? Exponential? What’s your baseline reference?

Pseudocode surfaces those questions before you waste time coding.

3. It makes collaboration easier

If you write pseudocode, someone else can review your logic before you invest hours in coding. You can catch flawed reasoning early.

[Pause]

Here’s the key insight: Good pseudocode can be translated into any programming language.

If your pseudocode is clear, converting it to R is almost mechanical. If your pseudocode is vague, your code will be vague too.

6 SLIDE 5: Pseudocode vs. Code vs. Prose

[0:14–0:18] — Three Modes of Thinking

Let’s look at the same task written three ways:

Chemistry example:

Prose (too informal): > “I’m going to remove the bad absorbance readings and then calculate the concentrations using the calibration curve.”

Pseudocode (just right): - Load absorbance data from instrument output - Remove rows where absorbance is negative (instrument error) - Remove rows where absorbance > 3.0 (out of linear range) - Apply calibration equation: concentration = (absorbance - 0.05) / 0.123 - Create scatterplot of concentration vs. time - Save plot to figures/concentration_timeseries.png

Code (too specific):

data <- read.csv("data/raw/absorbance.csv")
data_clean <- data %>% 
  filter(absorbance >= 0,
         absorbance <= 3.0) %>%
  mutate(concentration = (absorbance - 0.05) / 0.123)
ggplot(data_clean, aes(x = time, y = concentration)) +
  geom_point()
ggsave("figures/concentration_timeseries.png")

[Pause]

Notice that pseudocode has: - Verbs — “Load,” “Remove,” “Apply,” “Create,” “Save” - Specific conditions — “where absorbance is negative,” “absorbance > 3.0” - Clear outputs — “scatterplot,” “save to figures/” - Domain knowledge — “out of linear range,” “calibration equation”

It’s detailed enough to be unambiguous, but general enough that you’re not worrying about syntax.

7 SLIDE 6: Common Pseudocode Mistakes

[0:18–0:22] — What to Avoid

Let me show you some common mistakes people make when writing pseudocode.

7.1 Mistake 1: Too vague

Biology example: ❌ “Standardize the measurements”

That could mean anything. Be specific about what you’re standardizing and how.

✅ “Divide each bird mass by wing length to get body condition index”

Chemistry example: ❌ “Normalize the data”

What kind of normalization?

✅ “Divide each absorbance value by the maximum absorbance to scale from 0 to 1”

7.2 Mistake 2: Too detailed (actually writing code)

Biology example: ❌ “Use filter() to subset where count >= 5”

That’s code, not pseudocode. You’re worrying about syntax before you’ve clarified the logic.

✅ “Remove sites with fewer than 5 observations”

Chemistry example: ❌ “Use mutate() to create new column with pH = -log10(H_concentration)”

✅ “Calculate pH from hydrogen ion concentration”

7.3 Mistake 3: Skipping steps

Biology example: ❌ “Load field data, make species accumulation curve”

What happened in between? Did you clean it? Aggregate by site? Calculate richness?

✅ “Load field data → Remove incomplete surveys → Count species per site → Calculate cumulative species richness → Plot accumulation curve”

Chemistry example: ❌ “Load titration data, determine pKa”

Too many hidden steps!

✅ “Load pH and volume data → Identify equivalence point → Calculate half-equivalence pH → Report pKa value”

7.4 Mistake 4: No decision points

Biology example: ❌ “Remove rare species”

How do you define rare? What’s your cutoff?

✅ “Remove species that occur in fewer than 3 sites (less than 10% of total sites)”

Chemistry example: ❌ “Remove bad datapoints”

What makes a datapoint “bad”?

✅ “Remove datapoints where pH meter error flag is TRUE or pH change > 2 units between consecutive readings”

[Pause]

The pattern here: Good pseudocode makes all decisions explicit.

STEP 2: Count the number of observations for each species

STEP 4: Keep only the top 10 species
STEP 5: Create a bar chart with species on x-axis, count on y-axis

9 SLIDE 8: Identifying Ambiguity in Pseudocode

[0:36–0:42] — Debugging Bad Pseudocode

Now let’s look at some pseudocode that has problems. I want you to spot the ambiguity.

Example 1 (Chemistry):

Load the titration dataset
Clean the pH data
Calculate the equivalence point
Plot the titration curve

What’s wrong with this? Type in the chat.

[Wait for responses]

Exactly! It’s way too vague. What does “clean” mean? How do you calculate equivalence point? What kind of plot?

Example 2 (Biology):

Load temperature data from field sensors
Remove outliers
Calculate average temperature by site
Make a plot

Better, but still problems. What’s ambiguous here?

[Wait for responses]

Right! How do we define outliers? Are we using standard deviations? Domain knowledge? And what kind of plot?

Here’s a better version:

Load temperature data from field sensors
Remove temperatures below -50°C or above 60°C (sensor error range)
Remove temperatures more than 3 standard deviations from site mean
Calculate mean temperature for each site
Create a bar plot of mean temperature by site (ordered north to south)
Save plot to figures/temp_by_site.png

Much clearer!

Example 3 (Chemistry):

Load absorbance spectra
Correct for baseline
Find peak wavelength
Save results

What’s missing here?

[Wait for responses]

Better version:

Load absorbance spectra from UV-Vis instrument
Subtract minimum absorbance (wavelength 800-900 nm) from all values
Identify wavelength with maximum absorbance in range 400-700 nm
Extract absorbance value at peak wavelength
Save wavelength and absorbance to data/processed/peak_data.csv

12 SLIDE 11: Pseudocode as a Tool for Debugging

[1:12–1:15] — Beyond Planning

Here’s something I want you to remember:

Pseudocode isn’t just for planning. It’s also for debugging.

When your code isn’t working, the problem is usually one of two things:

  1. Your logic is flawed — you’re asking the computer to do the wrong thing
  2. Your syntax is wrong — you’re asking correctly but using the wrong words

If you have pseudocode, you can separate these problems:

  • Go back to your pseudocode and ask: “Is this what I actually want to do?”
  • If the pseudocode is right but the code is wrong, it’s a syntax problem (easier to fix with Google/ChatGPT)
  • If the pseudocode is wrong, fix the logic first, then rewrite the code

Chemistry example: - Pseudocode says: “Calculate molarity from mass and volume” - But you forgot: “First convert mass to moles using molecular weight” - That’s a logic error, not a syntax error!

Biology example: - Pseudocode says: “Calculate species richness per site” - But you forgot: “First remove duplicate observations of same species at same site” - Fix the logic, then fix the code!

This saves hours of frustration.
