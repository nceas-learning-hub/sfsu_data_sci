What Is a Project?

A self-contained folder containing everything needed to reproduce an analysis

  • Self-contained = All files in one folder

  • Everything needed = Data, scripts, outputs, documentation

  • Organized logically = Clear structure

  • For someone else = Collaborator, reviewer, future-you

Projects answer:

1. What data? → data/ folder

2. What did I do? → documented in scripts

3. What did I produce? → saved in figures/

A Well-Organized Project

bee_diversity_analysis/
├── data/
│   ├── raw/                # Original, untouched
│   └── processed/          # Cleaned data
├── scripts/
│   ├── 01_clean_data.R     # Numbered = order
│   ├── 02_calculate_richness.R
│   └── 03_make_figures.R
├── figures/
├── README.md               # START HERE
└── bee_diversity.Rproj     # RStudio project

✅ Clear hierarchy | ✅ Protected raw data | ✅ Numbered scripts | ✅ Self-documenting

Raw vs. Processed Data

data/
├── raw/         # What you started with
└── processed/   # What you created

Raw data = from field/lab/instrument
→ Never changes. Ever.

Processed data = created by cleaning raw data
→ Result of running a script

Golden rule:
Delete processed data and regenerate it by running scripts.

From now on: Raw data is read-only.

All changes in code.

Absolute Paths (BAD)

This only works on MY computer:

# BAD - Absolute path
data <- read.csv("/Users/gretchen/Desktop/bee_analysis/data/raw/bees.csv")

Error on your computer:

Error: cannot open file '/Users/gretchen/Desktop/...': 
No such file or directory

Why? You don’t have a user named “gretchen”

Relative Paths (GOOD)

This works on ANYONE’s computer:

# GOOD - Relative path
data <- read.csv("data/raw/bees.csv")

Why it works:
“Starting from the project folder, go into data/, then raw/, read bees.csv”

Works on any computer, any operating system!

Why Relative Paths Save Your Life

With absolute paths:

  1. Analysis at school: C:/Users/Student/.../data.csv
  2. Work at home → ERROR (different path)
  3. Fix all paths manually
  4. Back at school → ERROR (wrong again)
  5. Email advisor → ERROR (doesn’t have your folders)

With relative paths:

  1. Analysis at school: "data/raw/data.csv"
  2. Work at home → ✅ Works
  3. Back at school → ✅ Works
  4. Email advisor → ✅ Works

Every Project Needs a README

README.md is the first thing anyone reads

Answers four questions:

  1. What is this project about?

  2. What data does it use?

  3. How do I run the analysis?

  4. Who do I contact?

    Without README: Confusion and frustration
    With README: Clear path forward

Bad README Example

# My Project

This is my analysis.

This tells you nothing:

- What’s the research question?

- What data?

  • How to run it?

- Who made it?

Useless!

Good README Example

# Bee Diversity in Urban Gardens

## Overview
Analysis of bee species richness across 45 urban garden 
sites in San Francisco, May–August 2023.

Research question: Does richness differ between 
community gardens and private yards?

## Data
- Raw: `data/raw/bee_surveys.csv` (field surveys)
- Processed: `data/processed/bee_clean.csv` 

## Scripts (run in order)
1. `01_clean_data.R` - Removes incomplete surveys
2. `02_calculate_richness.R` - Rarefied richness
3. `03_make_figures.R` - Generates figures

## Contact
Gretchen LeBuhn (lebuhn@sfsu.edu)

Project Structure Checklist

Every project needs:

Folders:

- [ ] data/raw/ — original, never modified

- [ ] data/processed/ — cleaned/transformed

- [ ] scripts/ — numbered if order matters

- [ ] figures/ — all plots

Files:

- [ ] .Rproj file - [ ] README.md

- [ ] Descriptive file names

Code:

- [ ] Relative paths only

- [ ] Scripts numbered

- [ ] Comments explain decisions

Common Mistakes to Avoid

❌ Working outside project folder
Quick plot saved to Desktop → lost forever

❌ Using absolute paths
C:/Users/You/... → won’t work for others

❌ Editing raw data
Fix typo in Excel, save → reproducibility destroyed

❌ No README
6 months later, no idea what anything does

❌ Too many versions
analysis_final_REALLY_final_v3.R
