Visualization is an Ethical Practice


Tufte’s central argument:

Charts shape how people think, reason, and make decisions.
Therefore, how you present data is a moral responsibility — not just an aesthetic choice.

Three big themes:

Theme Core idea
Graphical Excellence Information-rich; complex ideas with clarity, precision, efficiency
Graphical Integrity Represent quantities honestly and proportionally
Analytical Design Support serious thinking: comparisons, patterns, layered detail

When Visualization Fails: The Challenger

January 28, 1986. Engineers had data showing O-ring failure rates increased at lower temperatures. The launch forecast was colder than any prior launch.

The data was spread across 13 disconnected charts. The pattern was invisible. The launch was approved. Seven astronauts died.

Tufte’s analysis: a single scatter plot of temperature vs. O-ring damage across all prior launches would have made the risk immediately visible.


“Clarity, precision, and efficiency” — these are not just aesthetics.
They determine whether evidence can actually be seen and used.

Tufte’s Three Concepts to Know


Data-Ink Ratio
Maximize the share of ink devoted to actual data.
Erase anything that can be removed without losing information.

→ In ggplot2: theme_minimal(), theme_classic()


Chartjunk
Decorative elements that add visual noise without adding information.
3D effects · unnecessary gridlines · rainbow fills · decorative shadows

→ Avoid: 3D charts, overly colorful default themes


Small Multiples
The same chart repeated for different subgroups — enables comparison across categories simultaneously.

→ In ggplot2: facet_wrap() — this is literally Tufte’s small multiples

Tufte’s Ideas Live Inside ggplot2


The Grammar of Graphics framework and Tufte’s principles emerged from the same intellectual tradition.

When you use:

  • theme_minimal() → you are maximizing the data-ink ratio
  • facet_wrap() → you are making small multiples
  • scale_fill_viridis_d() → you are serving graphical integrity (accessibility)
  • labs(title = ..., subtitle = ...) → you are following clear, detailed labeling


Understanding Tufte helps you understand why ggplot2 is designed the way it is.

The Grammar of Graphics

ggplot2 is a system for declaratively creating graphics.

You provide:

  • The data
  • How to map variables to aesthetics
  • What graphical primitives to use

…and it takes care of the details.


Declarative = describe what you want,
not how to draw it step by step.

Four Essential Components — Every ggplot


1. ggplot() — tells R we are making a ggplot

2. data = — what data frame are we using?

3. aes() — aesthetics mapping: which variables map to x, y, color, fill, size…?

4. geom_*() — geometry: what type of plot are we making?


Layers are added with + — different from the pipe %>%

ggplot(data = my_data, aes(x = var1, y = var2)) +
    geom_point()

colnames(delta_visits)

Is This Data Tidy?

Recall the three tidy data principles:

  1. Every column is a variable
  2. Every row is an observation
  3. Every cell is a single value

Look at these columns: sm_boat, med_boat, lrg_boat, bank_angler, scientist, cars

These are all values of a single variable: visitor type
Their counts are all values of another variable: quantity

→ This is wide format. We need long format for ggplot2.

“ggplot2 for the most part likes data input to be in a long format.”

pivot_longer() — Wide to Long


visits_long <- delta_visits %>%
    pivot_longer(
        cols = c(sm_boat, med_boat, lrg_boat,
                 bank_angler, scientist, cars),
        names_to  = "visitor_type",
        values_to = "quantity"
    ) %>%
    rename(restore_loc = eco_restore_approximate_location) %>%
    select(-notes)

Result: 55 rows × 13 columns → 330 rows × 8 columns

Same information — better organized for plotting.

When visitor_type is a variable, we can map it to color.
When it’s a column name, we can’t.

Exercise 1: Calculate Daily Visit Totals


Calculate the daily visits by restore_loc, date, and visitor_type.

daily_visits_loc <- visits_long %>%
    group_by(restore_loc, date, visitor_type) %>%
    summarise(daily_visits = sum(quantity))

head(daily_visits_loc)

daily_visits_loc is our plotting data frame for the rest of the week. Every geom layer, every color mapping, every facet draws from this tidy, summarized object.

Our First ggplot


Three equivalent ways to write the same plot — all produce the same result:

# Option 1 — data and mapping in ggplot() [preferred]
ggplot(data = daily_visits_loc,
       aes(x = restore_loc, y = daily_visits)) +
    geom_col()

# Option 2 — mapping in geom
ggplot(data = daily_visits_loc) +
    geom_col(aes(x = restore_loc, y = daily_visits))

# Option 3 — everything in geom
ggplot() +
    geom_col(data = daily_visits_loc,
             aes(x = restore_loc, y = daily_visits))

The + Operator — Layering Logic


Each + adds a new layer on top of the previous one.

Think of it like overlays in GIS, or adding stains to a microscopy slide — each layer adds information.

General layer order:

ggplot()  +  geoms  +  scales  +  labs  +  theme


⚠️ Common error: Using %>% instead of + between ggplot layers.
%>% passes data between functions.
+ adds layers to a plot.

Changing Geoms — Same Grammar, Different Plot

Once you know the grammar, changing plot type is trivial — swap the geom_*().

# Boxplot — distributions across categories
daily_visits_loc %>%
    filter(daily_visits < 30,
           visitor_type %in% c("sm_boat", "med_boat", "lrg_boat")) %>%
    ggplot(aes(x = visitor_type, y = daily_visits)) +
    geom_boxplot()
# Violin — same data, shape of distribution
    ggplot(aes(x = visitor_type, y = daily_visits)) +
    geom_violin()
# Line + Point — time series (two geoms, one plot)
daily_visits_loc %>%
    filter(restore_loc == "Decker Island",
           visitor_type == "med_boat") %>%
    ggplot(aes(x = date, y = daily_visits)) +
    geom_line() +
    geom_point()

Geoms for Scientific Work


Geom Use for
geom_col() / geom_bar() Categorical counts or values
geom_point() Scatter plots
geom_line() Connected series, time trends
geom_boxplot() Distributions across groups
geom_violin() Distribution shape across groups
geom_histogram() Single variable distribution
geom_smooth() Trend lines with confidence intervals
geom_errorbar() Uncertainty / error bars
