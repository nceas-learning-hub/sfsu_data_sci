Creating Professional Figures

Figures in Quarto = automatic, reproducible

Advantages:

  • Consistent sizing
  • Proper captions
  • Cross-referenceable
  • Updates automatically with data

No more: Saving plots, resizing, copy/pasting

Basic Figure Creation

In Visual Editor:

  1. Write your plotting code inside a code chunk
  2. Click the gear icon ⚙️ on the chunk
  3. Set Label to fig-richness (must start with fig-)
  4. Set Caption to your figure caption
  5. Set Width and Height (in inches)

Key: The fig- prefix is what makes it cross-referenceable!

Under the Hood

The gear icon writes these chunk options for you: #| label: fig-richness, #| fig-cap: "...", #| fig-width: 8, #| fig-height: 6

Figure Chunk Options

Some available in the chunk gear icon ⚙️ dialog:

  • Width / Height — size in inches (e.g., 8 × 6)
  • Aspect ratio — alternative to setting both dimensions
  • Caption — text that appears below the figure
  • Alignment — center, left, or right (dropdown)

Use the dialog instead of memorizing syntax!

Under the Hood

#| fig-width: 8      # Width in inches
#| fig-height: 6     # Height in inches
#| fig-cap: "Your caption here"
#| fig-align: center  # or left, right

Multiple Figures in One Chunk

After setting name in the chunk gear icon ⚙️ dialog:

  1. Set the main Caption (overall figure caption)
  2. Add Subcaptions — one per plot in the chunk
  3. Set Layout columns to 2 for side-by-side

Result: Two plots side-by-side with individual subcaptions and one shared caption

Under the Hood

#| label: fig-comparison
#| fig-cap: "Comparison of pH and dissolved oxygen"
#| fig-subcap:
#|   - "pH by site"
#|   - "Dissolved oxygen by site"
#| layout-ncol: 2

Cross-Referencing Figures

Step 1: Make sure your figure chunk has a fig- label (via the gear icon)

Step 2: In your text, type @ — an autocomplete menu appears!

  • Lists all your labeled figures, tables, and equations
  • Select the one you want (e.g., fig-temperature)
  • Quarto inserts the reference for you

Result: “As shown in Figure 1, temperature…” with automatic numbering — if you reorder figures, numbers update!

Under the Hood

In source mode, you type @fig-temperature directly in your markdown text.

Creating Tables in Quarto

Three approaches:

  1. Markdown tables — Visual Editor: Table → Insert Table (spreadsheet-like grid!)
  2. knitr::kable() — from R data frames (most common)
  3. gt package — publication-quality formatting

Today: Focus on kable + the Visual Editor tools

Basic Table with kable

In Visual Editor:

  1. Write your R code that produces a table using kable()
  2. Click the gear icon ⚙️ on the chunk
  3. Set Label to tbl-summary (must start with tbl-)
  4. Set Caption to your table caption

Key: The tbl- prefix is what makes tables cross-referenceable — same pattern as fig- for figures!

Under the Hood

#| label: tbl-summary
#| tbl-cap: "Summary statistics by site"

Formatting Tables with kableExtra

Table styling is done in R code (not the Visual Editor):

library(kableExtra)

kable(summary_stats, 
      digits = 2,
      col.names = c("Site", "Mean", "SD"),
      caption = "Species richness statistics") %>%
  kable_styling(bootstrap_options = c("striped", "hover")) %>%
  column_spec(1, bold = TRUE) %>%
  row_spec(0, bold = TRUE, background = "#D3D3D3")

Result: Professional table with striping, hover, and bold formatting

Cross-Referencing Tables

Same workflow as figures!

  1. Make sure your table chunk has a tbl- label (via gear icon)
  2. In your text, type @
  3. The autocomplete menu shows all tbl-, fig-, and eq- labels
  4. Select your table reference

Result: “Statistical analysis (Table 1) revealed…”

Numbers update automatically if you reorder!

Under the Hood

In source mode: Statistical analysis (@tbl-anova) revealed significant differences among sites (p < 0.001).

Adding Equations

In Visual Editor:

Inline math: Use Insert → Inline Math (or the Σ toolbar button) — type your LaTeX in the pop-up with live preview

Display math (centered): Use Insert → Display Math — opens a larger editor for block equations

Both give you a live preview as you type the LaTeX!

Under the Hood

Inline: $H' = -\sum p_i \ln(p_i)$

Display:

$$
H' = -\sum_{i=1}^{S} p_i \ln(p_i)
$$

Numbered & Cross-Referenced Equations

In Visual Editor:

  1. Insert a display equation using Insert → Display Math
  2. After the closing $$, add a label: {#eq-shannon}
  3. Reference it in text by typing @ and selecting eq-shannon

Result: Numbered equation that you can reference just like figures and tables!

Under the Hood

$$
H' = -\sum_{i=1}^{S} p_i \ln(p_i)
$$ {#eq-shannon}

As shown in @eq-shannon, diversity depends on...

Callout Blocks

In Visual Editor:

  1. Go to Insert → Callout
  2. Choose the type from the dropdown: note, warning, tip, important, caution
  3. Add a title and your content

The fenced div syntax is created automatically!

Great for: Data limitations, methods notes, analysis suggestions

Under the Hood

:::{.callout-warning}
## Data Limitation
Sample sizes varied by site due to weather.
:::

Adding Citations

In Visual Editor:

  1. Go to Insert → Citation
  2. Search by DOI, browse your .bib file, or connect to Zotero
  3. Select your reference — the [@key] syntax is inserted automatically

Setting up the bibliography:

  • Click the gear icon ⚙️ next to the Render button
  • Set the Bibliography field to your .bib file

No need to edit YAML by hand!

Under the Hood

YAML: bibliography: references.bib

In text: Urban bees are declining [@Smith2020].

Page Layout Options

In Visual Editor:

Two-column layout: Insert → Div, set class to .columns, then nest two divs with class .column and set width attributes

Margin content: Insert → Div with class .column-margin

The Visual Editor creates the fenced div syntax for you — no counting colons!

Under the Hood

:::: {.columns}
::: {.column width="50%"}
Left column content
:::
::: {.column width="50%"}
Right column content
:::
::::

Code Folding for Readers

Document-level setting:

  • Click the gear icon ⚙️ next to the Render button
  • Enable Code Fold and Code Tools

Per-chunk setting:

  • Click the gear icon ⚙️ on any code chunk
  • Toggle Code Fold on
  • Set a custom Code Summary label (e.g., “Show data cleaning code”)

Result: Readers see a button to reveal code if interested

Under the Hood

YAML: code-fold: true and code-tools: true

Per chunk: #| code-fold: true and #| code-summary: "Show data cleaning code"

Document Themes

In Visual Editor:

  1. Click the gear icon ⚙️ next to the Render button
  2. Open the document properties dialog
  3. Set Theme (cosmo, flatly, journal, litera, minty, etc.)
  4. Optionally add a Custom CSS file

Popular themes: cosmo, flatly, litera, minty

Under the Hood

---
format:
  html:
    theme: cosmo
    css: styles.css
---

Table of Contents

In Visual Editor:

  1. Click the gear icon ⚙️ next to the Render button
  2. Enable Table of Contents
  3. Set Depth (how many heading levels to include)
  4. Set Location (left, right, or body)

Sections become clickable navigation — great for long documents!

Under the Hood

---
format:
  html:
    toc: true
    toc-depth: 3
    toc-location: left
    toc-title: "Contents"
---

Tabbed Content

In Visual Editor:

  1. Insert → Div with class .panel-tabset
  2. Inside the div, add ## headings for each tab
  3. Put content (plots, tables, code) under each heading

Result: Content organized in clickable tabs — saves space!

Under the Hood

::: {.panel-tabset}
## Plot
(plot code here)

## Data
(data code here)
:::

Complete Analysis Workflow

Typical structure:

  1. Introduction (context, questions)
  2. Methods (data collection, analysis approach)
  3. Results (with ?@fig-xxx and ?@tbl-xxx references)
  4. Discussion (interpretation)
  5. Conclusion
  6. References (auto-generated)

All from one .qmd file — all manageable in Visual Editor!

Advanced Best Practices

✅ Label everything via the gear icon (fig-, tbl-, eq-)

✅ Use descriptive labels (fig-temperature not fig-plot1)

✅ Write clear captions (complete sentences, in the gear dialog)

✅ Cross-reference liberally (type @ to find labels)

✅ Keep code chunks focused (one plot per chunk)

✅ Use Insert → Callout for important notes

✅ Set code-folding in document properties for technical reports

Debugging Complex Documents

Strategy:

  1. Render frequently (catch errors early)
  2. Comment out sections to isolate problems
  3. Check chunk labels in the gear dialog (no duplicates!)
  4. Verify file paths (data, images, bib)
  5. Look at error line numbers in render log

Common issue: Duplicate chunk labels cause silent failures

Tip: Switch to Source mode to check the raw markdown when debugging tricky problems

Outputting to PDF

Requirements: Install tinytex: quarto install tinytex

In Visual Editor:

  1. Click the gear icon ⚙️ next to the Render button
  2. Change format to PDF
  3. Set options like document class and margins

Great for submission to journals!

Under the Hood

---
format:
  pdf:
    documentclass: article
    geometry: margin=1in
    keep-tex: true
---

Outputting to Word

In Visual Editor:

  1. Click the gear icon ⚙️ next to the Render button
  2. Change format to Word (docx)
  3. Optionally set a reference template and enable TOC

Useful for: Sharing with non-technical collaborators, manuscript submissions requiring Word, making final formatting tweaks

Cross-references still work in Word!

Under the Hood

---
format:
  docx:
    reference-doc: template.docx
    toc: true
---
